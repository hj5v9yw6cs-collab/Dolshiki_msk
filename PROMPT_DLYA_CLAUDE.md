# Промпт для Claude: платформа автоматизации юркомпании по защите дольщиков

> **Как этим пользоваться.**
> 1. Открываете Claude (claude.ai или Claude Code) и вставляете **весь текст ниже**, начиная с раздела «=== НАЧАЛО ПРОМПТА ===».
> 2. Claude задаст 8–10 уточняющих вопросов (список в конце промпта) — ответьте на них, это критично, иначе он начнёт угадывать.
> 3. Дальше работайте **по фазам** (Фаза 0 → Фаза 5). Не просите сделать всё за один раз — получите нерабочий комок кода.
> 4. Если нужен быстрый старт без чтения всего — в конце файла есть «КОРОТКАЯ ВЕРСИЯ» на 15 строк.
>
> **Важно, прочитайте до отправки:**
> - Все юридические параметры (ставки ЦБ, периоды мораториев, размеры штрафов) в промпте даны **как черновик конфига и подлежат проверке вашим юристом**. Они меняются постановлениями правительства, поэтому в ТЗ прямо заложено требование: не хардкодить их в коде, а держать в редактируемом файле/админке.
> - Вы будете обрабатывать паспорта, ДДУ и платёжные документы клиентов — это персональные данные. В промпте есть отдельный раздел по 152-ФЗ (хостинг в РФ, согласие, уведомление в РКН). Не выкидывайте его.
> - Любой сгенерированный документ (претензия, иск) — **черновик под проверку юриста**, а не готовый к подаче документ. Это требование зашито в ТЗ на уровне интерфейса.

## === НАЧАЛО ПРОМПТА ===

Ты — senior full-stack инженер и системный аналитик. Помоги мне спроектировать и построить внутреннюю платформу автоматизации для моей юридической компании.

### 1. Контекст бизнеса

Я владелец юридической компании по защите прав дольщиков. Офисы: **Казань и Москва**, дела ведём также по Санкт-Петербургу и области. Своего сайта пока нет — его тоже нужно сделать.

Наши услуги (это же — структура разделов сайта):
- Недостатки в отделке от застройщика (взыскание стоимости устранения)
- Неустойка по 214-ФЗ (Москва / СПб / Казань)
- Судебная практика: недостатки в отделке; практика по 214-ФЗ
- Помощь в приёмке квартиры в новостройке
- Проверка (анализ) застройщика
- Калькулятор неустойки 214-ФЗ
- Анализ ЖК

Типовой жизненный цикл дела:
1. Лид с сайта / из мессенджера → 2. Консультация, сбор документов → 3. Досудебная претензия застройщику → 4. Ожидание ответа (срок) → 5. Экспертиза (для недостатков отделки) → 6. Исковое заявление в суд → 7. Заседания → 8. Решение → 9. Исполнительный лист / взыскание → 10. Расчёт с клиентом.

### 2. Что нужно построить

Единая система, которая закрывает четыре блока. **Главная боль: сейчас всё вручную** — документы клиентов лежат в переписках, реестр дел ведётся руками, претензии и иски набиваются копипастой из старых файлов.

**Модуль A. Публичный сайт / лендинги услуг** — маркетинговая витрина с формами захвата заявок и SEO-структурой под перечисленные выше услуги.

**Модуль B. Калькулятор неустойки по 214-ФЗ** — публичный, встраиваемый на сайт, с захватом контакта для получения детального расчёта.

**Модуль C. Приём и обработка заявок (CRM-ядро)** — заявки с сайта, воронка, карточка дела, задачи, сроки, уведомления.

**Модуль D. Документооборот и автоматизация (ключевой для меня)** — приём документов от клиента, автоматическая раскладка и переименование, ведение реестра в Excel, генерация претензии и искового заявления по шаблонам.

Требования:

### 4. Модуль B — Калькулятор неустойки (спроектируй особенно тщательно)

#### 4.1 Два режима расчёта

**Режим 1 — неустойка за просрочку передачи объекта (ст. 6 ч. 2 214-ФЗ).**

Вход:
- цена договора (ДДУ), ₽
- дата передачи объекта по договору (плановая)
- дата фактической передачи (или «объект не передан» → считать по сегодняшний день)
- статус дольщика: физлицо / юрлицо
- (опционально) ставка ЦБ, заданная вручную — с подсказкой, какую подставляет система

Базовая формула, которую нужно реализовать:

```
Неустойка = Цена ДДУ × Дни просрочки × (1 / 300) × Ставка_ЦБ × K
где K = 2 для дольщика-физлица, K = 1 для юрлица
```

**Режим 2 — расходы и неустойка по недостаткам отделки (ст. 7, ст. 10 214-ФЗ).**

Вход: стоимость устранения недостатков по заключению эксперта, дата вручения требования застройщику, дата фактического удовлетворения (или «не удовлетворено»), стоимость экспертизы.
Выход: сумма устранения + неустойка за просрочку удовлетворения требования + расходы на экспертизу.

#### 4.2 Обязательное требование: юридические параметры — только в конфиге

Ставки ЦБ, периоды мораториев и размеры штрафов **меняются постановлениями правительства**. Поэтому:
- Ни одно из этих значений не должно быть зашито в коде расчёта.
- Всё лежит в отдельном версионируемом конфиге (`legal-config.json` или таблица в БД) с полями `действует_с`, `действует_по`, `основание` (номер закона/постановления), `комментарий`.
- В админке — экран редактирования этого конфига для юриста, с логом изменений (кто/когда/что поменял).
- В расчёте на каждый параметр — ссылка на основание, чтобы в суде можно было объяснить цифру.

Ниже — **черновик стартового конфига. Это мои рабочие заметки, а не проверенные данные: при реализации пометь каждую строку флагом `requires_lawyer_review: true` и выведи в админке предупреждение, пока юрист их не подтвердит.**

  ],

#### 4.3 Логика расчёта

1. Построить период просрочки: `[дата_по_договору + 1 день ; дата_факта или сегодня]`.
2. Вычесть из него все пересечения с периодами мораториев из конфига.
3. Если период просрочки разрывается мораторием — считать **по сегментам**, для каждого сегмента своя ставка и свой множитель, затем суммировать.
4. Применить `rate_cap`, если он задан для сегмента.
5. Отдельно рассчитать: штраф (% от присуждённой суммы), моральный вред (поле с ручным вводом, по умолчанию пусто), расходы (экспертиза, госпошлина, представитель) — все как отдельные строки.
6. Округление — до копеек, банковское округление; в итоговой сумме отдельно показать «итого к взысканию».

#### 4.4 Ставка ЦБ

- Тянуть ключевую ставку автоматически (источник — открытые данные ЦБ РФ, XML/SOAP-сервис `cbr.ru`), кешировать, обновлять по расписанию раз в сутки.
- Если источник недоступен — падать на значение из конфига и **показывать в UI, что ставка взята из кеша с такой-то даты**. Никогда не считать молча по устаревшей ставке.

#### 4.5 Вывод результата

- Итоговая сумма крупно + разбивка по сегментам в виде таблицы: период, дней, ставка, основание, сумма.
- Явная сноска: какие периоды исключены как мораторные и на каком основании.
- Дисклеймер: «Предварительный расчёт. Не является юридической консультацией. Итоговую сумму суд может снизить по ст. 333 ГК РФ.»
- Кнопка **«Получить детальный расчёт с юристом»** → форма (имя + телефон) → создаётся лид в CRM, а расчёт сохраняется и прикрепляется к лиду.
- Кнопка **«Скачать расчёт PDF»** — расчёт в виде приложения к исковому (табличная форма, пригодная для приобщения к делу).
- Виджет должен встраиваться на существующий сайт через `<iframe>` или один `<script>`-тег — на случай, если основной сайт пока останется как есть.

#### 4.6 Тесты (обязательны)

Покрой расчётный модуль юнит-тестами, минимум эти случаи:
1. Просрочка целиком внутри моратория → неустойка 0.
2. Просрочка целиком до моратория → расчёт по одной ставке.
3. Просрочка, разорванная мораторием на два сегмента → сумма двух сегментов.
4. Ставка менялась внутри периода просрочки → сегментация по ставкам.
5. Юрлицо vs физлицо → множитель 1 vs 2.
6. Объект не передан на сегодня → верхняя граница = текущая дата.
7. Дата факта раньше даты по договору → просрочки нет, 0, без отрицательных значений.
8. Високосный год, границы периодов (день начала и день окончания включительно/исключительно — зафиксируй правило явно и протестируй).

### 5. Модуль C — Заявки и CRM-ядро

- Единый инбокс лидов: формы сайта, калькулятор, входящие из WhatsApp/Telegram, звонки (если подключим телефонию), почта.
- Автораспределение лида на юриста: по региону (Москва / Казань / СПб) и типу услуги, с ручным переназначением.
- Воронка (стадии): Новый → Квалификация → Договор → Сбор документов → Претензия → Ожидание ответа → Экспертиза → Иск подан → Заседания → Решение → Исполнительный лист → Деньги получены → Закрыто. Стадии настраиваются.
- Карточка дела: клиент, объект (ЖК, корпус, квартира), застройщик, реквизиты ДДУ, суммы (цена ДДУ, расчёт неустойки, заявлено, присуждено, получено), ответственный юрист, документы, задачи, лента событий, суд и номер дела.
- Сроки и напоминания: срок ответа на претензию, дата заседания, срок обжалования, срок предъявления ИЛ. Напоминания в Telegram и на почту за N дней (N настраивается).
- Уведомления клиенту о смене стадии (шаблоны сообщений, отправка в один клик — не автоматом).
- Личный кабинет клиента: статус дела, список требуемых документов с галочками, загрузка файлов, скачивание готовых документов, история.

### 6. Модуль D — Документооборот и генерация документов (ядро автоматизации)

#### 6.1 Приём документов

Каналы: личный кабинет, ссылка на загрузку (без регистрации, одноразовый токен), Telegram-бот, почтовый ящик `docs@` (парсинг вложений).

#### 6.2 Автоматическая классификация и раскладка

При загрузке файла система должна:
1. Определить тип документа: ДДУ, доп. соглашение, акт приёма-передачи, смотровой лист / дефектная ведомость, паспорт, платёжное поручение / чек, ипотечный договор, заключение эксперта, претензия, ответ застройщика, определение суда, решение суда, исполнительный лист, доверенность, прочее.
   - Реализация: сначала — правила (по имени файла, ключевым словам в тексте после OCR/парсинга PDF), затем — LLM-классификатор по извлечённому тексту. Всегда возвращать **уверенность**; если ниже порога — файл падает в очередь «требует ручной проверки», а не проставляет тип молча.
2. Извлечь ключевые реквизиты (номер и дата ДДУ, цена, стороны, адрес объекта, срок передачи) и подставить их в карточку дела — **как предложение к подтверждению**, с подсветкой «извлечено автоматически, проверьте».
3. Переименовать по шаблону: `{Фамилия}_{НомерДела}_{ТипДокумента}_{ДатаДокумента}.pdf` (шаблон настраивается).
4. Разложить в структуру папок дела:
   ```
   /Дела/{Год}/{Фамилия И.О.}_{НомерДела}/
       01_Договор/
       02_Оплата/
       03_Приемка/
       04_Экспертиза/
       05_Претензия/
       06_Суд/
       07_Исполнение/
       99_Прочее/
   ```
5. Показать в карточке дела чек-лист: каких документов для текущей стадии не хватает (комплектность под претензию / под иск — разные наборы).

#### 6.3 Реестр в Excel

- Ведение сводного реестра дел в `.xlsx` — автогенерация по кнопке и по расписанию.
- Колонки: № дела, дата, ФИО клиента, телефон, регион, ЖК/объект, застройщик, тип услуги, стадия, юрист, цена ДДУ, период просрочки, расчёт неустойки, заявлено, присуждено, получено, гонорар, суд, № судебного дела, дата заседания, комплектность документов, дата последнего действия, комментарий.
- Отдельные листы: «Дела», «Реестр документов», «Финансы», «Календарь заседаний».
- Форматирование: заморозка шапки, автофильтр, условное форматирование (просроченные сроки — красным), суммы — денежный формат.
- Синхронизация двусторонняя не нужна: БД — источник истины, Excel — выгрузка. Но выгрузка должна быть по фильтру (период, юрист, регион, стадия).
- Дополнительно: экспорт в Google Sheets по расписанию (если подключим Google-аккаунт).

#### 6.4 Генерация претензии и искового заявления

Это то, ради чего всё строится.

- Шаблоны в `.docx` с плейсхолдерами (`{{ФИО_клиента}}`, `{{Номер_ДДУ}}`, `{{Сумма_неустойки}}`, `{{Таблица_расчета}}` и т.д.). Шаблоны загружает и редактирует юрист через админку, программист для этого не нужен.
- Набор шаблонов на старте: досудебная претензия (неустойка), досудебная претензия (недостатки отделки), исковое заявление (неустойка), исковое заявление (недостатки), расчёт неустойки (приложение к иску), ходатайство о назначении экспертизы, заявление о выдаче исполнительного листа, доверенность.
- Подстановка данных из карточки дела + результата калькулятора. Таблица расчёта вставляется как настоящая таблица Word, а не как текст.
- Вариативные блоки: включать/исключать абзацы по условиям (ипотека / без ипотеки, объект передан / не передан, физлицо / юрлицо, регион и подсудность).
- Автоподбор суда по адресу объекта и цене иска — **как подсказка с обязательным подтверждением юриста**, не автоматом.
- Выход: `.docx` (для правки) + `.pdf` (для отправки). Файл сразу кладётся в папку дела и в карточку.
- **Обязательно:** каждый сгенерированный документ помечается в системе как **ЧЕРНОВИК** и не может быть выгружен клиенту, пока юрист не нажал «Проверено юристом». В интерфейсе — явная плашка: «Документ сгенерирован автоматически и требует проверки юристом перед подачей».
- Версионирование: хранить все версии документа с указанием, кто и когда правил.
