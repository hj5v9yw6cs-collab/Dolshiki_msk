# Безопасность и персональные данные (152-ФЗ)

Система обрабатывает персональные данные клиентов: ФИО, телефон, почту, а начиная
с Фазы 3 — паспорта, ДДУ и платёжные документы. Ниже: что уже сделано в коде и что
обязан сделать оператор (компания) вне кода.

## Что реализовано в Фазе 1

| Мера | Где |
|---|---|
| Согласие на обработку ПДн обязательно, без него заявка отклоняется | `app/api/leads.py`, форма виджета |
| Фиксируется факт согласия: дата, IP, версия текста политики | `Lead.consent_at`, `consent_ip`, `consent_policy_version` |
| Админские эндпоинты закрыты токеном; без `ADMIN_TOKEN` отключены полностью | `app/api/deps.py` |
| Список заявок недоступен без токена | `app/api/leads.py` |
| Ограничение частоты отправки заявок (5 за 10 минут с адреса) | `app/api/deps.py` |
| Скрытое поле-ловушка против ботов | форма виджета |
| Ограничение доменов, которым разрешены запросы к API | `CORS_ORIGINS` |
| Журнал изменений юридического конфига (кто, когда, что) | `app/api/admin.py`, таблица `config_changes` |
| Валидация конфига до записи — сломанный конфиг не сохранится | `app/core/legal_config.py` |

## Что обязан сделать оператор до запуска

- [ ] **Уведомление в Роскомнадзор** об обработке персональных данных — проверить,
      подано ли; если нет, подать до начала обработки.
- [ ] **Хостинг в РФ.** База данных и файловое хранилище — на серверах на территории
      России (Selectel, Timeweb, Яндекс Облако, VK Cloud).
- [ ] **Тексты документов**, согласованные юристом: политика обработки ПДн, политика
      конфиденциальности, текст согласия. Версию текста проставлять в
      `consent_policy_version`, чтобы было видно, на что именно согласился клиент.
- [ ] **HTTPS** обязателен: сертификат, редирект с http, HSTS.
- [ ] **`ADMIN_TOKEN`** — длинная случайная строка, хранится вне репозитория,
      меняется при увольнении сотрудника, имевшего доступ.
- [ ] **Резервные копии** базы: ежедневно, в шифрованном виде, с регулярной проверкой
      восстановления. Бэкап, который ни разу не разворачивали, бэкапом не считается.
- [ ] **Срок хранения и удаление** данных по отзыву согласия — регламент и исполнитель.

## Обязательно к Фазе 3 (загрузка документов клиентов)

С момента, когда в систему попадут паспорта и договоры, требования ужесточаются:

- Шифрование файлов в хранилище (at-rest) с отдельными ключами доступа.
- Роли и разграничение доступа: юрист видит только свои дела, руководитель — все.
- Журнал доступа к документам: кто и когда открыл или скачал файл клиента.
- Ссылки на загрузку документов — одноразовые, с ограниченным сроком жизни.
- Антивирусная проверка загружаемых файлов.
- Отдельная процедура удаления документов при отзыве согласия.

## Правила разработки

- Персональные данные не пишутся в логи. В логах — идентификаторы (`lead.id`),
  не телефоны и не ФИО.
- Секреты — только через переменные окружения. `.env` в репозиторий не попадает
  (см. `.gitignore`), в репозитории лежит только `.env.example`.
- Файл `backend/data/app.db` с боевыми данными не коммитится.
- При добавлении нового эндпоинта, возвращающего данные клиентов, зависимость
  `require_admin` (позже — проверка роли) обязательна.
