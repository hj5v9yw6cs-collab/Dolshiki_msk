Что сделано, как это запустить и как проверить руками.

## Быстрый запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt

cp backend/.env.example backend/.env      # и впишите ADMIN_TOKEN
cd backend
ADMIN_TOKEN=dev-token ../.venv/bin/uvicorn app.main:app --reload --port 8000
```

- Калькулятор: http://localhost:8000/widget/index.html
- Документация API: http://localhost:8000/docs
- Проверка состояния: http://localhost:8000/health

Тесты:

```bash
cd backend && ../.venv/bin/python -m pytest -q
```

## Как проверить руками

1. Откройте калькулятор. Шаг 1 — выберите «Застройщик не передал квартиру в срок».
2. Шаг 2 — цена договора 8 500 000 ₽. Шаг 3 — срок передачи 30.12.2021, отметьте
   «объект уже передан по акту» и поставьте дату 15.09.2025. Нажмите «Рассчитать».
3. В результате должно быть три расчётных периода и три исключённых мораторных —
   расчёт обязан «перепрыгивать» мораторные периоды, а не считать их подряд.
   Итог: 2 174 725,00 ₽.
4. Нажмите «Расчёт для суда» — откроется печатная форма с таблицей, пригодной для
   приобщения к делу. Сохранение в PDF — через печать браузера.
5. Заполните заявку без галочки согласия — форма не даст отправить. С галочкой —
   заявка уходит и привязывается к расчёту.
6. Переключите тему кнопкой в шапке, обновите страницу — выбор должен сохраниться.
7. Заявки: `curl -H "Authorization: Bearer dev-token" http://localhost:8000/api/v1/leads`

## Ключевые решения

### Юридические параметры — только в конфиге

Ставки ЦБ, мораторные периоды, ограничения ставки, размер штрафа и правило подсчёта
дней лежат в `backend/config/legal-config.json`. В коде расчёта нет ни одной из этих
величин. У каждого блока есть `basis` (номер закона или постановления) и флаг
`requires_lawyer_review`.

Пока флаг стоит, расчёт выполняется, но в ответе API и на печатной форме появляется
предупреждение «параметр не подтверждён юристом». Снимать флаг — после сверки с
первоисточником. Правки идут через `PUT /api/v1/admin/legal-config`, конфиг
валидируется **до** записи, каждое изменение пишется в журнал (`config_changes`).

**Значения в конфиге на сегодня — черновик и требуют проверки.** Это относится и к
истории ключевой ставки, и к периодам мораториев, и к размеру штрафа.

### Как считается период

1. Начало — день, следующий за сроком передачи по договору (`start_offset_days`).
2. Конец — дата фактической передачи или сегодняшний день, если объект не передан.
3. Из периода вычитаются все мораторные периоды.
4. Если выбран режим «по каждому периоду своя ставка», остаток дополнительно режется
   по датам изменения ключевой ставки.
5. Каждый сегмент считается отдельно, суммы складываются.

Правило последнего дня зафиксировано явно: по умолчанию день передачи входит в
просрочку (`inclusive_both_ends`). Если ваш суд считает иначе, переключите
`day_count_rule.mode` на `exclusive_end` — результат уменьшится ровно на день,
это покрыто тестом.

### Режимы определения ставки

| Режим | Когда применять |
|---|---|
| `on_obligation_date` | по умолчанию — ставка на день исполнения обязательства по договору |
| `on_actual_date` | ставка на дату фактической передачи |
| `on_claim_date` | ставка на дату подачи иска |
| `per_segment` | по каждому периоду своя действовавшая ставка |
| `manual` | ставка введена вручную |

### Ставка ЦБ

`scripts/sync_rates.py` тянет ключевую ставку с cbr.ru (SOAP-метод `KeyRate`),
сжимает ежедневные значения в точки изменения и дописывает в конфиг. Ставится в cron
раз в сутки.

Если cbr.ru недоступен, расчёт **не останавливается**: берётся последняя известная
ставка из конфига, но `GET /api/v1/rate` возвращает `is_stale: true`, а виджет
показывает предупреждение. Молча считать по устаревшей ставке нельзя — цифра пойдёт
в суд.

## Встраивание на garantlc.ru

Вариант 1 — один тег:

```html
<div id="garant-calc"></div>
<script src="https://calc.garantlc.ru/embed.js"
        data-target="garant-calc"
        data-policy-url="https://garantlc.ru/policy"></script>
```

Вариант 2 — iframe напрямую:

```html
<iframe src="https://calc.garantlc.ru/widget/index.html"
        style="width:100%;border:0;min-height:640px" scrolling="no"></iframe>
```

Открыть сразу на нужном сценарии: `?mode=defects` или `?mode=delay`.

Домен сайта нужно добавить в `CORS_ORIGINS`, иначе браузер заблокирует запросы.

## Интерфейс виджета

Светлый минимализм: нейтральная серая шкала и один акцент (индиго `#4F46E5`).
Основное действие — почти чёрная кнопка, акцент работает на прогрессе, фокусе и
ключевых числах, чтобы внимание уходило на суммы.

**Пошаговый мастер, 4 шага:** Ситуация → Суммы → Даты → Результат. На первом шаге
человек выбирает сценарий крупными карточками, дальше показываются только поля
своего сценария. Редко нужные параметры (режим ставки, моральный вред, госпошлина,
представитель) убраны в блок «Дополнительные параметры».

**Темы:** светлая и тёмная. По умолчанию берётся системная, переключатель в шапке
запоминает выбор в `localStorage`. Тема применяется до первой отрисовки, поэтому
тёмная не мигает белым при загрузке.

**Мобильные:** таблицы расчёта превращаются в карточки — горизонтального скролла
нет ни на одном экране. Проверено на 390px.

Печатная форма расчёта намеренно оставлена в классическом виде (Times New Roman,
рамки таблиц): это приложение к исковому заявлению, и от него ждут вида судебного
документа, а не интерфейса.

## Ограничения этой фазы

Названы честно, чтобы не всплыли на внедрении:

- **PDF формируется печатью из браузера**, а не серверной генерацией файла.
  Полноценная выгрузка `.docx`/`.pdf` придёт в Фазе 4 вместе с шаблонами исков —
  там всё равно понадобится генератор документов.
- **Ограничение частоты запросов живёт в памяти процесса.** При запуске нескольких
  воркеров лимит начнёт считаться отдельно для каждого — тогда переносим на Redis.
- **Админка конфига — это API, без веб-интерфейса.** Экран для юриста делаем в Фазе 2
  вместе с остальной админкой, чтобы не рисовать интерфейс дважды.
- **Аутентификация — один админский токен.** Роли (`руководитель / юрист / помощник`)
  появятся в Фазе 2 вместе с карточкой дела.
- **Уведомления — только Telegram.** Почта и мессенджеры — по мере подключения каналов.
- **История ключевой ставки внесена вручную и требует сверки.** После первого запуска
  `scripts/sync_rates.py` данные подтянутся с cbr.ru.
